# Kubeconfig Reference — Role Examples

Generated kubeconfigs land here. Below are the **structure examples** for each role.
The actual files with real credentials are generated by `scripts/generate-kubeconfigs.sh`.

## senior-devops — Full Cluster Access

```yaml
# kubeconfig-senior-devops-user.yaml
# Permissions: All resources except RBAC write, secrets-write on production
# Default namespace: default (all namespaces accessible)
apiVersion: v1
kind: Config
current-context: senior-devops-user@rke2-prod
contexts:
  - name: senior-devops-user@rke2-prod
    context:
      cluster: rke2-prod
      user: senior-devops-user
      namespace: default
clusters:
  - name: rke2-prod
    cluster:
      server: https://<VIP>:6443
      certificate-authority-data: <CA_DATA>
users:
  - name: senior-devops-user
    user:
      client-certificate-data: <CERT>   # CN=senior-devops-user, O=senior-devops
      client-key-data: <KEY>
```

## Distribution & Security Notes

- Kubeconfigs contain private keys — treat as secrets (never commit to git)
- Rotate certificates at expiry using `generate-kubeconfigs.sh`
- For teams using SSO: replace cert-based auth with OIDC provider in kubeconfig
- Add this to `.gitignore`: `rbac/kubeconfigs/*.yaml`, `.secrets/`
